# Compiled Story Column Usage Audit

**Date:** 2025-01-27  
**Purpose:** Map all usage of `chimera_compiled_stories` table columns before refactoring

---

## Executive Summary

This audit maps how each column in the `chimera_compiled_stories` table is used throughout the application. The analysis covers:
- **Write Side:** Where columns are populated (Compiler)
- **Read Side:** Where columns are consumed (Game Loop, Services)
- **Client Side:** What data is sent to the frontend

**Key Finding:** `prompt_interpreter_logic` and `prompt_narrator_style` are **written but never read** at runtime. The MAS services build prompts dynamically from `config_engine` instead.

## 2. Detailed Column Analysis

### 2.1 `config_engine` (JSONB)

**Structure:**
```typescript
{
  runtime: {
    actions: Record<string, ActionDefinition>,  // Action definitions with logic
    schema: {...},                               // State schema
    logic: {...}                                 // Logic config (legacy)
  },
  creation: {
    fields: FormField[]                          // Character creation fields
  },
  active_rulesets: RulesetDefinition[]          // Source rulesets (for UI)
}
```

**Write Side:**
- **Location:** `backend/src/services/compiler/compiler.service.ts:303`
- **Method:** `StoryCompilerService.compileStory()`
- **Source:** Generated by `EngineRefiner.refine(rulesets)` (line 199)
- **Note:** Contains the full "cartridge" with merged ruleset data

**Read Side:**

1. **ResolutionService / DeterministicEngine**
   - **Location:** `backend/src/services/game/resolution.service.ts`
   - **Usage:** Does NOT directly read `config_engine`. Instead, receives `ActionDefinition` objects passed from GameLoopService
   - **Note:** The engine executes action logic but doesn't query the compiled story directly

2. **EngineService**
   - **Location:** `backend/src/services/runtime/engine.service.ts:18-81`
   - **Usage:** Receives `actionsMap` parameter (extracted from `config_engine` by GameLoopService)
   - **Extracts:** Action definitions from `actionsMap[actionSlug]` to execute deterministic logic

3. **GameLoopService**
   - **Location:** `backend/src/services/runtime/game-loop.service.ts:122-139`
   - **Usage:** Extracts `actions_map` from `compiledStory.master_schema.actions_map`
   - **Note:** `master_schema.actions_map` is derived from `config_engine.runtime.actions` during compilation
   - **Method:** `extractActionsMap()` converts the map to a format usable by MAS1 and Engine

4. **GameSetupService**
   - **Location:** `backend/src/services/game/setup.service.ts:57`
   - **Usage:** Reads `config_engine.creation.fields` for character creation UI
   - **Also reads:** `config_engine.runtime.schema` for state schema defaults (line 92-93)

5. **GameTurnService**
   - **Location:** `backend/src/services/game/turn.service.ts:42-65`
   - **Usage:** Reads `config_engine.runtime.logic` and `config_engine.actions` for action resolution
   - **Note:** This is a legacy/alternative path that may not be actively used

**Frontend Usage:**
- **CharacterCreatorPage:** Reads `config_engine.creation_manifest` (line 190-200)
- **StartGatewayPage:** Reads `config_engine.active_rulesets` for display (line 131, 144)
- **API Endpoints:** 
  - `GET /api/chimera/game/stories/:id` - Returns full compiled story including `config_engine`
  - `GET /api/chimera/compile/:storyId` - Returns full compiled story including `config_engine`

**Performance Concern:** ⚠️ **The entire `config_engine` JSONB blob is sent to the frontend**, which could be large (contains all action definitions, schemas, rulesets).

## 3. Redundancy Findings

### 3.1 Prompt Columns Are Redundant

**Finding:** `prompt_interpreter_logic` and `prompt_narrator_style` are **written but never read**.

**Evidence:**
- `Mas1Service.resolve()` builds prompts dynamically (lines 33-54 of `mas1.service.ts`)
- `Mas2Service.narrate()` builds prompts dynamically (lines 36-58 of `mas2.service.ts`)
- No code searches for or reads these columns from the database

**Impact:**
- Storage waste: Two TEXT columns storing potentially large prompt strings
- Maintenance burden: Prompts are compiled but never used
- Confusion: Future developers may assume these are used

**Recommendation:** 
- **Option A:** Remove columns entirely (if prompts are always built dynamically)
- **Option B:** Use these columns if we want to support pre-compiled prompts for performance
- **Option C:** Move prompts into `config_engine` if we want to keep them but reduce column count

---

### 3.2 `config_engine` Contains Redundant Data

**Finding:** `config_engine.active_rulesets` duplicates data that could be fetched from `ruleset_ids` column.

**Evidence:**
- `config_engine.active_rulesets` contains full `RulesetDefinition[]` objects (line 201 of compiler.service.ts)
- `chimera_compiled_stories.ruleset_ids` column stores the UUID array
- Frontend reads `config_engine.active_rulesets` for display (StartGatewayPage.tsx:131)

**Impact:**
- Storage duplication: Full ruleset definitions stored in JSONB when only IDs are needed
- Query performance: Frontend receives entire ruleset objects when it may only need IDs

**Recommendation:**
- Keep `ruleset_ids` column for filtering/querying
- Remove `active_rulesets` from `config_engine` if frontend can fetch rulesets separately when needed
- OR: Keep `active_rulesets` but make it optional/lazy-loaded

---

### 3.3 Frontend Receives Entire `config_engine` Blob

**Finding:** API endpoints return the full `config_engine` JSONB to the frontend, which may be large.

**Evidence:**
- `GET /api/chimera/game/stories/:id` returns full compiled story (chimera-game-init.ts:303)
- `GET /api/chimera/compile/:storyId` returns full compiled story (chimera-compile.ts:173)
- Frontend only uses:
  - `config_engine.creation_manifest` (CharacterCreatorPage)
  - `config_engine.active_rulesets` (StartGatewayPage)
  - `config_engine.creation.fields` (CharacterCreatorPage)

**Impact:**
- Network overhead: Sending entire action library, schemas, and rulesets to client
- Parse time: Frontend must parse large JSONB blob
- Security: Exposes internal action definitions and logic to client

**Recommendation:**
- Create optimized endpoints that return only needed data:
  - `/api/chimera/game/stories/:id/manifest` - Returns only `creation_manifest` and `snapshot_world`
  - `/api/chimera/game/stories/:id/rulesets` - Returns only `active_rulesets` (if needed)
- Keep full endpoint for backend/internal use only

## 4. Refactoring Recommendations

### 4.1 Safe Column Splitting

**Proposed Split:**
```
config_engine (current)
  ↓
config_mechanics (Engine-only)
  - runtime.actions
  - runtime.schema
  - runtime.logic

config_interpreter (MAS1-only)
  - prompt_rules
  - available_actions
  - available_entities

config_narrator (MAS2-only)
  - prompt_rules_with_guardrails
  - rag_index (lore fragments)
```

**Safety Analysis:**

✅ **SAFE** - The split aligns with actual usage:
- **ResolutionService/EngineService** only needs `config_mechanics.runtime.actions`
- **Mas1Service** builds prompts dynamically (doesn't use pre-compiled prompts)
- **Mas2Service** builds prompts dynamically (doesn't use pre-compiled prompts)
- **GameSetupService** needs `config_mechanics.creation.fields` (can stay in mechanics)

⚠️ **CONSIDERATION:** If we split, we need to ensure:
1. `GameLoopService.extractActionsMap()` can still access actions from `config_mechanics`
2. Frontend endpoints can still return needed data (or we create optimized endpoints)

**Migration Path:**
1. Add new columns: `config_mechanics`, `config_interpreter`, `config_narrator`
2. Populate new columns during compilation (split `config_engine`)
3. Update read paths to use new columns
4. Deprecate `config_engine` (keep for backward compatibility)
5. Remove `config_engine` after migration period

---

### 4.2 Remove Redundant Prompt Columns

**Recommendation:** Remove `prompt_interpreter_logic` and `prompt_narrator_style` columns.

**Rationale:**
- Not read by any runtime code
- MAS services build prompts dynamically
- Reduces storage and maintenance burden

**Migration Path:**
1. Verify no external tools/dashboards depend on these columns
2. Remove from compiler write path
3. Drop columns from database schema
4. Update API response types (remove from CompiledStory type)

---

### 4.3 Optimize Frontend Data Transfer

**Recommendation:** Create lightweight endpoints for frontend consumption.

**New Endpoints:**
```
GET /api/chimera/game/stories/:id/manifest
  Returns: { creation_manifest, snapshot_world }

GET /api/chimera/game/stories/:id/setup
  Returns: { creation_manifest, snapshot_world, active_rulesets (IDs only) }
```

**Benefits:**
- Reduced payload size
- Faster page loads
- Better separation of concerns (backend vs frontend data)
