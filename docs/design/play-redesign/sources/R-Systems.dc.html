Same components, different data, so a new ruleset needs no new screen.

Custom systemsAuthors compose their own profile: pick modules, name stats and resources, choose dice visibility. Unknown ruleset fields fall back to a generic label and value row, so nothing breaks.
Engine contractEach ruleset ships a hud manifest beside its state_readout: module ids, field paths, labels, max values and display hints. The frontend renders manifests; it never hardcodes a system.
Stays constantBonds, dossiers, journal, Here panel and composer exist in every profile. Relationship tracking is the floor; stat systems are layered on top.
