Text pipelineMake the prose machine-readable without making it worseLet the model write freely, then let deterministic code decide what is a name, who is speaking and what was learned. Links never depend on the model being right.

1Narrator emits
Backend, modelWrites prose with light tags for scene, speaker, voice and entity refs. Tags carry ids the engine handed it, never invented ones.
2Stream parser
Backend, streamingTolerates half-open tags. Text streams to the client at once; a tag is held until it closes, so a raw brace never shows.
3Entity linker
Backend, deterministicValidates every id against Tier 0 and 1. Then scans untagged text against the alias table for names the model forgot to tag.
4Persist
Backend, databaseStores typed blocks and a mentions list with the turn. Mentions write to the knowledge log that feeds dossiers.
5Render
FrontendBlock components draw each type. Entity runs become buttons, hydrated lazily from a cached entity map.
Where to do the work
ApproachStrengthWeaknessVerdict
A. Narrator tags everythingCan mark speakers, tone, new entities and voices.Model drops or invents tags. Ids can be wrong.Use for structure only, always validated.
B. Deterministic linkerCheap, fast, never hallucinates. Uses your alias table.Cannot find brand new names. Ambiguity needs rules.Always on. The safety net.
C. Second model passCan tag unknown entities and pronouns.Adds latency and cost to every turn.Optional, background only, for re-parsing history.
D. Client regexNo backend change.Divergent behaviour, no persistence, no knowledge log.Avoid. Only as offline fallback.
RecommendationHybrid: Narrator tags structure (A), the server validates and links (B), and a background pass (C) can repair old turns. The client only ever renders validated blocks.
Streaming rules
›Plain first. Deltas render as text immediately. Links appear when a paragraph finalises, with a soft fade.
›Ordered. Each block has an id and sequence so late annotations patch the right place.
›Resumable. A reload replays stored blocks, not raw text.
›No cancel. Matches the UX spec. A failed turn shows retry, not partial links.
Edge cases
›Ambiguity. Two Brams, or "the stranger". Link asks once; the engine can pin one.
›Density. Link first mention per paragraph only, capped, honouring the reader setting.
›Possessives and plurals. Match Kiera's and taverns via stems on the alias table.
›Spoilers. Unidentified entities link under the alias the player has seen, never the true name.
›Edits. Author renames keep ids, so old turns still resolve.
Asks of the engine
›Alias table per story. Names, titles, nicknames, per entity, with a visibility flag.
›Ref tags in prompts. Narrator receives ids and allowed tags with the Tier 1 context.
›Block schema. Shared types package for backend and frontend.
›mentions table. Entity, turn, block, source, so dossiers can list where you learned each fact.
›Provisional entities. Director approves new: refs before they become real.
