# Project Chimera - Architecture Documentation

## Overview

Project Chimera is a greenfield implementation of a game authoring and runtime system. This document defines the core architectural concepts and terminology.

## Glossary

### Story Dimension

The **Story Dimension** is the container for a complete game experience. It encompasses:

- **World**: The setting, geography, history, and physical laws
- **Forces**: The mechanical systems, rules, and constraints that govern gameplay
- **Elements**: The entities, objects, and interactive components within the world
- **Lore**: The narrative knowledge, stories, and cultural context that enrich the experience

A Story Dimension represents a fully self-contained game universe that can be authored, compiled, and executed.

### Casting Circle

The **Casting Circle** is the authoring workflow and wizard interface for creating Story Dimensions. It provides:

- Step-by-step guidance for authors
- Validation and preview capabilities
- Integration with the compiler pipeline
- Asset management and organization

The Casting Circle is the primary interface through which content creators build and configure their games.

### Compiler (4-Step)

The **Compiler** is a four-step process that transforms raw authoring data into an executable Story Dimension:

1. **Base Load**: Ingests all source materials (world definitions, rulesets, entities, lore fragments)
2. **Resolution**: Resolves dependencies, conflicts, and references between components
3. **Master Schema**: Generates the unified schema that defines valid game state and actions
4. **Entity Filter**: Applies filtering and transformation rules to produce the final entity set

The compiler ensures consistency, validates constraints, and produces a deterministic, runnable game package.

### Runtime Loop

The **Runtime Loop** is the execution cycle that processes player actions and generates narrative responses:

- **MAS1 (Interpreter)**: Parses player input, extracts intent, and identifies the requested action
- **Engine (Deterministic Resolver)**: Applies game rules, resolves mechanics, and computes state changes
- **MAS2 (Narrator)**: Generates narrative text, contextual descriptions, and story continuations based on the resolved state

This loop runs continuously during gameplay, maintaining game state and producing coherent narrative experiences.

### Tiers

The system operates on two distinct tiers that separate mechanical and narrative concerns:

- **Tier 1 (Mechanical/Strict)**: Contains deterministic, rule-bound state (HP, inventory, time, stats). Changes are computed by the Engine and must be consistent and verifiable.

- **Tier 0 (Narrative/Flexible)**: Contains flexible, narrative-driven state (memories, relationships, story flags). Changes are generated by MAS2 and can be more interpretive and contextual.

This separation allows for strict mechanical integrity while preserving narrative flexibility.
